# ADR-0001: один пример арены — батч строк датасета

- Статус: accepted
- Дата: 2026-11-04

## Контекст

Оценщик арены запускает отдельный одноразовый контейнер на каждый пример (`common/runner-contract.md`, `common/isolation.md`) и перебирает примеры одного кандидата последовательно (`evaluator/service.py`, цикл по `examples`). Параллельные слоты распределяют разных кандидатов, а не примеры одного.

Замер на рабочей машине: `docker run` готового `arena-runner:local` с пустым `solve.py` — около 0.9 с. Наш public — 27 943 строки, private — 27 948. При строке-примере одна public-оценка заняла бы около 7 часов только на запуск контейнеров, плюс загрузку обученной модели кандидата на каждой строке. При лимите в десятки решений это неделя на public.

Пример-на-контейнер в арене нужен для задач, где решение примера длится минутами (LLM-харнес): независимость примеров, учёт времени и токенов на пример, повтор отдельного примера. У нас решатель без модели, без сети, наружу уходит только число.

## Решение

Строки split'а склеиваются в батчи, и каждый батч — один пример арены. Код арены не меняется.

- Сборка: `python3 case/dataset/batch.py` после `generate.py`; параметры и хэши — в `case/dataset/batches.json`.
- Строки перемешиваются хэшем `sha256(seed:id)`, батч — до 500 строк и до 400 000 символов `input` (предел арены 500 000). Итог: train 174, public 61, private 61 батч.
- `input` — JSON-строка `{"rows": [{"id", "prompt", "model", "input_tokens"}, ...]}`, `meta` в батч не попадает.
- `reference` — JSON-строка `{"output_tokens": {"<row id>": [длины ответов], ...}}`.
- Ответ решателя — JSON-строка `{"<row id>": предсказание_в_токенах, ...}` для каждой строки батча.
- Метрика (`kind: command`) на батч возвращает только `statistics` (сумма ошибок, число строк), а `aggregation` делит общую сумму на общее число строк. Итог — глобальный MAE по `log1p`, а не среднее средних по батчам разного размера.

## Альтернативы

- Строка = пример, полный public: ~7 часов на кандидата. Отвергнуто.
- Строка = пример, подвыборка public 10 %: ~45 минут, но шум парной разницы растёт с 0.006 до 0.019 SE, различимы только улучшения от ~0.05.
- Переиспользование контейнера в коде арены: нарушает правило AGENTS.md не менять общий протокол под кейс, и на защите это уже «своя арена».

## Последствия

- Public и private оцениваются целиком за минуты; train-сервис берёт подвыборки батчами (`--example-id train-0001`).
- Время решателя измеряется на батч, а не на строку. Для сравнения кандидатов этого достаточно; при равном MAE арена сравнивает суммарное время.
- Кандидат видит до 500 чужих строк сразу. Решению запрещено использовать соседние строки батча (статистики по батчу, трансдуктивное обучение): предсказание строки зависит только от её `input`. Это проверяет ревьюер, а тест кандидата — что предсказание строки не меняется при перестановке и прореживании батча.
- Пропущенная или лишняя строка в ответе, нечисловое или отрицательное предсказание — невалидный ответ; правило штрафа фиксирует метрика до заморозки.
- Нарезка — часть версии данных: менять seed и лимиты внутри кампании нельзя.
