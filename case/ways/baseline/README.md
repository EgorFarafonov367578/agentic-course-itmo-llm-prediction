# Baseline

Одни и те же квантили 0.1 / 0.5 / 0.9 длины ответа по train для каждой строки, без признаков. Медиана — baseline из ТЗ, интервал — простейший честный способ заполнить `lo` и `hi`. Это нижняя планка для всех направлений поиска.

`fit.py` считает квантили по `castillo.train.jsonl` и пишет `params.json`: каждая запись длины имеет вес `1/k`, где `k` — число ответов строки, поэтому это оптимальная константа именно для метрики, которая усредняет сначала по ответам строки, затем по строкам. Получены значения `lo=59`, `pred=367`, `hi=779` на 83 813 строках.

`solve.py` читает только `params.json` и по протоколу немодельного runner отдаёт `{"<id>": {"pred", "lo", "hi"}}` для каждой строки батча. Предсказание строки не зависит от соседей; это проверяет `case/tests/test_baseline.py`.

```bash
python3 case/ways/baseline/fit.py --train case/dataset/data/castillo.train.jsonl
```

Результат baseline на полной метрике: train `1.5089`, public `1.4792`, private `1.4848`. MAE на public — `0.743`. Для сравнения: оракул, который знает квантили собственных ответов каждой строки, даёт MAE `0.152` и полный score около `0.282`.

Baseline не зарегистрирован в журнале: он становится решением кампании только после `propose` поисковым запуском и занимает одно место в лимите.
