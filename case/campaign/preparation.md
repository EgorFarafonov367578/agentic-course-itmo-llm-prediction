# Подготовка AR-09 / c1

Статус на 06.11.2026: **подготовка кейса завершена, поиск ещё не запускался.** В каноническом журнале арены 0 из 40 предложений, public и private ещё не подключены к рабочему контуру, поэтому запуск поиска должен остановиться на проверке готовности.

## Условия

- Release ID: `ar09-c1-v1`.
- Метрика: `ar09-quantile-v1`, `minimize`, пакет `case/metric/`.
- Данные: split `castillo-sanitized-family-split-v2`, батчи `castillo-batched-v2`.
- Train / public / private: 83 813 / 27 905 / 27 906 строк; 175 / 60 / 59 батчей.
- Лимит решений: 40; финалистов `K=5` включая baseline; итоговых `N=5`.
- Решатель и метрика без LLM. Модель исследователей: Claude Opus 5.5, Claude Code.
- Runner: 4 CPU, 4 ГБ RAM, 256 pids, без сети, `/tmp` 512 МиБ, 120 секунд на батч; метрика — 30 секунд на батч и 120 секунд на агрегацию.

## Данные

Проверки открытого train в арене (`acceptance/data_check.py`) прошли все 17 пунктов: хэши файлов совпадают с `manifest.json` и `batches.json`, 83 813 строк с уникальными id, 175 батчей, id входа и эталона совпадают, нарезка воспроизводится побайтно. В строках от 5 до 30 длин: 82 816 строк с 10, 170 с 20, 12 с 30 и одна строка с 14 длинами. Последняя появилась из-за склейки двух прогонов до фильтра `MIN_OUTPUTS`; на метрику это не влияет.

Проверка split по локальным данным подтвердила: семейства train / public / private не пересекаются, все id уникальны, батчи покрывают каждую строку ровно один раз, хэши совпадают с manifest. Воспроизводимая проверка — `case/dataset/tests/test_data_integrity.py`.

## Runner и сервисы

Образ `arena-ar09-runner:c1-20261104` собран из `arena-main/cases/ar09/harness`. В нём Python 3.12.16, табличный стек и три закреплённые CPU-модели эмбеддингов. Проверка контейнера: cgroup 4 CPU / 4 ГиБ / 256 pids, UID 10001, сети нет, запись только в `/tmp`; время батча от 0.5 с у baseline до 37.8 с у e5-small на 500 строках, запас до лимита 120 с более чем трёхкратный.

Train-сервис подготовлен на `http://127.0.0.1:18990`. Синтетическая приёмка `submit → train_wait → result → журнал` прошла для baseline, baseline + файл 256 МиБ, мусорного ответа и падающего `solve.py`; статусы и score совпали с прямым расчётом. Синтетическая проверка public/private прошла `pack → submit → wait` и авторизованный `search-readiness` с условиями кампании. Настоящий private-допуск не расходовался.

## Smoke и известные ограничения

В записи подготовки арены `uv run python -m evaluator.smoke` отмечен как passed, `uv run pytest` — 1750 passed. При повторной проверке 06.11.2026 тесты кейса (`92 passed`) и pyright (`0 errors`) воспроизведены; повторный smoke в текущей сессии завис в `TestClient` и был остановлен по таймауту.

Граница изоляции в этой установке организационная: исследователь, оператор и Docker работают под одной учётной записью, а у исследователя есть интернет. Контейнер не даёт сети и ограничивает ресурсы, но не скрывает закрытые каталоги от того же пользователя. Для жёсткой изоляции public/private и state нужно держать под отдельной учётной записью или на другой машине.

## Что осталось оператору

1. Подключить public и private на данных `castillo-batched-v2` с тем же образом, метрикой, release ID и лимитами.
2. Выполнить авторизованный `search-readiness` private и записать дату, команду и ответ без токена.
3. Выдать исследователю public- и private-токены.
4. Запустить поиск отдельной командой по `case/campaign/start.md`.

Полные журналы подготовки и приёмки находятся в `arena-main/cases/ar09/campaigns/c1/preparation.md` и `arena-main/cases/ar09/acceptance/`.
