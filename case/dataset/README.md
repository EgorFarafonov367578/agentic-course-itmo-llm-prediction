# Данные

## Источник
[CASTILLO](https://huggingface.co/datasets/danfperam/castillo) ([статья](https://arxiv.org/abs/2505.16881)), лицензия CC BY 4.0. Берётся конфигурация `sanitized`, ревизия `fb93f412e6bed3f3b834f0ded23e0865c286ed6c`. Хэши исходных файлов записаны в [manifest.json](manifest.json).

- 13 open-source моделей: Qwen2.5 7B/14B/32B, Llama 3.1-8B / 3.2-1B / 3.2-3B / 3.3-70B, Gemma-3 4B/12B, Phi-4-mini, Mistral-7B, Ministral-8B, Mixtral-8x7B.
- 11 395 запросов из 7 источников. Обычные запросы: Alpaca, Dolly, ShareGPT. Задачи на код: Apps, BigCodeBench, MBPP, DS-1000.
- На каждую пару «запрос × модель» сгенерировано **10 ответов** и записаны их длины в токенах. 207 пар (почти все из ShareGPT) сгенерированы повторно в разных файлах CASTILLO с тем же `sample_id`: запрос и параметры совпадают, длины разные. Такие повторы склеиваются в одну строку с 20 или 30 длинами — это та же пара с тем же распределением, просто выборка больше. Обоснование — в [ADR-0002](../../docs/adr/0002-merge-repeated-pairs.md). Параметры генерации свои у каждой модели (Qwen: 0.7/0.8/20, Llama: 0.6/0.9/50, остальные: 1.0/1.0/50). Они лежат в `meta.decoding` и однозначно определяются моделью, поэтому отдельным признаком не служат.
- Лимит генерации около 15 000 токенов. В `sanitized` убраны вырожденные ответы (зацикливание, упор в лимит), поэтому обрезанных ответов почти нет.

Свои ответы не генерируются: ресурсов на это нет, а 10 готовых ответов на пару закрывают оговорку из ТЗ про случайность длины.

Сборка воспроизводится одной командой: скачивание (около 650 МБ), семейства, split, запись JSONL и manifest. Занимает около минуты плюс скачивание, зависимостей нет, нужен только Python 3.10+.

```bash
python3 case/dataset/generate.py
```

Результат появляется в `case/dataset/data/castillo.{train,public,private}.jsonl`. Сырые данные лежат в `case/dataset/raw/`. Обе папки в git не попадают. Сборка детерминирована: при повторном запуске совпадают хэши файлов в manifest.

## Одно распределение
Все три раздела — случайное разбиение одного источника по семействам. Перемешивание делается хэшем `sha256(seed:family_id)`. Разбиение стратифицировано по источнику запросов: внутри каждого источника семейства по очереди жадно отдаются тому разделу, который сильнее всего отстаёт от целевой доли строк (60 / 20 / 20). Поэтому доли источников в разделах совпадают с точностью до долей процента.

Распределения длин ответов в разделах тоже совпадают:

| Split | p25 | p50 | p75 | p90 | p99 |
|---|---|---|---|---|---|
| train | 177 | 367 | 556 | 778 | 1638 |
| public | 190 | 382 | 559 | 772 | 1607 |
| private | 190 | 377 | 554 | 757 | 1616 |

## Семейства
Семейство — это связная компонента графа запросов, где ребро соединяет запросы с коэффициентом Jaccard ≥ 0.3 по словесным 5-граммам. Кандидаты в пары ищутся через инвертированный индекс по шинглам. Шинглы, которые встречаются больше чем в 1000 запросах (общая обвязка источника), для поиска кандидатов не используются, но в Jaccard учитываются.

Почему деление по семействам. В источниках много шаблонных серий:
- Dolly: «Identify which instrument is string or percussion: …»;
- MBPP: «Write a python function to count …»;
- DS-1000: варианты-пертурбации одной задачи;
- ShareGPT: продолжения одного диалога.

Длина ответа у таких запросов почти одинаковая, и kNN по эмбеддингам выучил бы её запоминанием, если бы серия разошлась между train и private. Все 13 моделей одного запроса тоже всегда попадают в один раздел.

Итог: 10 013 семейств, из них 523 содержат больше одного запроса. Самое большое семейство — 85 запросов MBPP с общим началом формулировки. Проверка после сборки: пар запросов из **разных** разделов с Jaccard ≥ 0.3 — 0. Ближайшие межсплитовые пары (Jaccard около 0.29) совпадают только общими оборотами вроде «What is the difference between tennis …».

## Отбор строк
Отбрасываются 29 строк (0.02 %), у которых после очистки осталось меньше 5 ответов из 10 (`MIN_OUTPUTS`). У остальных строк от 5 до 30 ответов: у 99 % — ровно 10, у 207 склеенных повторов — 20 или 30.

Gemma-3-12B и Llama-3.2-1B прогнаны не на всех запросах. Это свойство источника, восполнять его не нужно.

## Размеры и обоснование
| Split | Строк (запрос × модель) | Запросов | Семейств | Почему столько |
|---|---|---|---|---|
| train | 83 813 | 6 875 | 5 814 | Основная часть: на ней учатся модели (регрессия, kNN, квантили), исследователь делает свои подвыборки и CV по семействам |
| public | 27 905 | 2 267 | 2 108 | Достаточно, чтобы различать близких кандидатов (см. ниже); оценка дешёвая |
| private | 27 906 | 2 253 | 2 091 | Той же точности, что public, чтобы сравнение train / public / private (B-6.5) было честным |

Шум метрики (MAE по `log1p(токенов)`) оценён бутстрепом по семействам на public:
- абсолютное значение MAE у простого предсказателя: SE около 0.013;
- **парная** разница двух кандидатов на одних и тех же строках, а именно так сравниваются кандидаты в кампании: SE около 0.006 на полном public, 0.009 на половине, 0.019 на 10 % (замерено на паре «медиана по модели» против «медиана по модели × источнику»). На полном public различимы улучшения от примерно 0.015 (2.5 SE).

Ориентиры качества на public:

| Предсказатель | MAE log1p |
|---|---|
| Медиана по всему train (baseline из ТЗ) | 0.743 |
| Медиана по модели | 0.734 |
| Медиана по паре «модель × источник» | 0.635 |
| Оракул: медиана записанных ответов той же пары | 0.152 |

Оракул — нижняя граница ошибки любого предсказателя: остаток приходится на случайность самой генерации.

Стоимость прогона: на каждый раздел нужно около 28 тысяч предсказаний. Для табличных моделей это секунды, для эмбеддингов на CPU — минуты. Ограничение на время предсказания задаёт метрика.

## Батчи для арены
Оценщик арены запускает отдельный контейнер на каждый пример, поэтому одна строка датасета не может быть примером арены: public шёл бы часы. Строки склеиваются в батчи до 500 строк и 400 000 символов, и каждый батч — один пример арены. Обоснование и формат ответа — в [ADR-0001](../../docs/adr/0001-batched-examples.md).

```bash
python3 case/dataset/batch.py
```

Скрипт читает `data/castillo.{split}.jsonl` и пишет `data/castillo.{split}.batched.jsonl`; параметры и хэши — в [batches.json](batches.json). Получается 175 / 60 / 59 батчей для train / public / private. Нарезка детерминирована, строки перемешаны хэшем `sha256(seed:id)`, поэтому каждый батч — смесь источников и моделей. В батч попадают только `input` и `reference`, `meta` остаётся в исходных JSONL.

## Формат
UTF-8 JSONL, одна запись на пару «запрос × модель»:
```json
{
  "id": "0003246a0acc1e9d",
  "input": {"prompt": "QUESTION: You are given an integer array nums ...", "model": "meta-llama/Llama-3.3-70B-Instruct", "input_tokens": 194},
  "reference": {"output_tokens": [452, 417, 439, 512, 736, 447, 606, 407, 657, 833]},
  "meta": {"prompt_id": "b1d70f2e1f2dcbb9", "family": "b1d70f2e1f2dcbb9", "source": "Apps", "category": "undefined",
           "decoding": {"temperature": 0.6, "top_p": 0.9, "top_k": 50}}
}
```

Поля разделены по доступности:
- **`input`** получает решатель. `input_tokens` — длина запроса токенизатором этой же модели, она доступна и в реальном использовании.
- **`reference`** решателю не передаётся, по нему считает метрика.
- **`meta`** — служебные поля. В train исследователь видит их целиком (например, `family` для CV). Можно ли использовать `source` как признак, решается в описании кейса.

Public и private хранятся у оценщика, вне репозитория и вне доступа исследователя.

**Важно для изоляции.** CASTILLO открыт, поэтому любой, у кого есть доступ к Hugging Face и этот скрипт, может восстановить эталоны public и private. Исследователям нельзя давать сеть к `huggingface.co` и доступ к `case/dataset/raw/` и `case/dataset/data/`, кроме train.
